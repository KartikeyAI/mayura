# @mayura/ag-ui

Private workspace package bundled as `mayura/ag-ui`. Experimental AG-UI **1.0** Fetch adapter over the scoped native server, with run lifecycle/step events, authoritative thread message snapshots, final released text, scoped state snapshots/deltas, permissioned frontend tools and approval interrupts/resume. No AG-UI SDK or additional infrastructure dependency.

See [the public guide](../../docs/guides/ag-ui.md) for mounting, permissions, limits, continuing budgets, same-origin authentication and uncertain approval recovery. Native run records own submission idempotency and tool-write claims. The adapter closes observers, never the host server or native run.

Protocol design reviewed 2026-10-20 against the [AG-UI 1.0 schema](https://docs.ag-ui.com/spec/1.0/schema) and [interrupt/resume contract](https://docs.ag-ui.com/concepts/interrupts). This is a version-pinned subset; full protocol and SDK conformance are not claimed. Multimodal input and incremental token streaming remain outside this slice.

Offline regression cases are authored under `test/`. Local offline validation passed; see [release validation status](../../docs/guides/release-readiness.md) for remaining qualifications.

State synchronization is opt-in (`ag-ui:state` plus a scoped host `read` source), with optional shared core `thread/read_state` authorization and auditing. Each request starts from an authoritative snapshot; later versions produce bounded RFC 6902 deltas or a full resync. Browser state is an ignored echo. Source reads are timed, scoped and bounded across streams; uncooperative callbacks retain their pool slot until settled. No application-state writes, tool replay or budget reset is introduced. State semantics follow the pinned [1.0 state events and JSON Patch schema](https://docs.ag-ui.com/spec/1.0/schema), reviewed 2026-10-20.

Frontend tools use a bounded live bridge (`createAgUiFrontendTools`) pinned to one agent, normal native tool/effect/budget admission, mandatory scoped core frontend policy, and a one-shot browser helper (`createAgUiFrontendExecutor`). Claims precede browser execution; bounded client results resume the existing native run and pass its output schemas/guards. Supply a shared `FrontendToolStore` from `createAggregateFrontendToolStore` (`mayura/storage-contracts`, grant `frontend-tools:store`) for durable one-time claims and atomic result outboxes across HTTP replicas. The native execution owner polls the journal; its loss leaves evidence for reconciliation without native or browser replay. Delivery reservations never transfer, and do not attest validation/thread completion. `outboxes()` exposes authorized metadata; `purgeExpired()` redacts payloads while retaining permanent tombstones. Omitting the store retains the process-local mode and its session-affinity requirement. See the guide for mounting the claim route, result continuations, cancellation and retention. Protocol behavior follows the [official frontend tool/result contract](https://docs.ag-ui.com/concepts/tools), reviewed 2026-10-20.

Opt-in `nativeRecovery: { permissions: { allow: ['ag-ui:frontend-recover'] } }` parks root frontend calls in the native thread checkpoint store before dispatch. A new native owner consumes the saved result and continuation once with the original budget/history. Scoped `runs:resume` commands and the trusted `kind: 'frontend'` recovery worker use fenced checkpoint consumption; neither browser writes nor completed paid work is replayed. Post-consume uncertainty remains reconciliation-only. See [safe native-owner recovery](../../docs/guides/ag-ui.md#safe-native-owner-recovery). Local offline validation passed; see [release validation status](../../docs/guides/release-readiness.md) for remaining qualifications.
