## Required work queue

1. **Complete:** packed `@mayura/helpers` covers configuration, secret references, retry/deadline/cancellation, cleanup, polling, pagination, safe artifact transfer, provider-schema binding, redacted logging and budget-aware concurrency. Unit, no-phone-home and isolated offline consumer evidence pass.
2. **In progress:** `@mayura/cli` now provides plan/apply initialization, bounded static configuration validation/inspection and all eight required credential-free starters. The installed two-package CLI profile and all eight workspace-linked executions pass. Authenticated serve/worker/run/approval/cache/evidence/migration commands and all-template execution from packed dependency closures remain.
3. **Complete:** provider diversity includes fixed-destination OpenAI Responses and Anthropic Messages adapters plus an exact loopback-only OpenAI-compatible Chat Completions path. All credentials, models, pricing and schemas are explicit; deterministic unit and isolated packed-consumer evidence pass. Live accounts/models, local runtime interoperability and model-quality evaluation remain part of item 7.
4. **Complete for the remote-index profile:** Mem0, Supermemory.ai and OpenViking adapters use explicit network authority and opaque scope namespaces. Every remote hit is rehydrated through the exact current native version/hash; tombstones and stale/cross-scope hits cannot re-enter context. Deterministic provider tests and an isolated packed consumer pass. Live editions, deletion SLAs, data residency and semantic quality remain item 7 qualification work.
5. Complete missing workflow/human lifecycle primitives and operational adapters: workflow timers, loops/compensation, pause/resume plus human client transports, credential stores, blob storage, authenticated deduplicated webhooks, triggers, health probes and tool catalogs. The driver-free typed information/correction/plan-selection WorkStream boundary is complete with paired adapter and isolated packed-consumer evidence.
6. Complete UI bindings and OpenTelemetry traces/metrics while preserving browser/server and audit/telemetry boundaries.
7. Define and execute the complete performance/evaluation suite, protected CI release workflow and first registry-provenance rehearsal.

Every item requires public contracts, denied/failure-path tests, packed-consumer evidence, documentation and a local Git checkpoint. This file must be updated as each slice closes; the active development goal remains open until every roadmap item has direct evidence.
