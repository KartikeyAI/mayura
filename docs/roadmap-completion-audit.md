## Required work queue

1. **Complete:** packed `@mayura/helpers` covers configuration, secret references, provider-neutral use-scoped credential resolution, retry/deadline/cancellation, cleanup, polling, pagination, safe artifact transfer, provider-schema binding, redacted logging and budget-aware concurrency. Unit, no-phone-home and isolated offline consumer evidence pass.
2. **In progress:** `@mayura/cli` now provides plan/apply initialization, bounded static configuration validation/inspection, all eight required credential-free starters, authenticated health/tool/human operations and ephemeral run inspection/bounded wait/single-attempt cancellation. The installed two-package CLI profile and all eight workspace-linked executions pass. Authenticated serve/worker/durable-run/exact-approval/cache/evidence/migration commands and all-template execution from packed dependency closures remain.
3. **Complete:** provider diversity includes fixed-destination OpenAI Responses and Anthropic Messages adapters plus an exact loopback-only OpenAI-compatible Chat Completions path. All credentials, models, pricing and schemas are explicit; deterministic unit and isolated packed-consumer evidence pass. Live accounts/models, local runtime interoperability and model-quality evaluation remain part of item 7.
4. **Complete for the remote-index profile:** Mem0, Supermemory.ai and OpenViking adapters use explicit network authority and opaque scope namespaces. Every remote hit is rehydrated through the exact current native version/hash; tombstones and stale/cross-scope hits cannot re-enter context. Deterministic provider tests and an isolated packed consumer pass. Live editions, deletion SLAs, data residency and semantic quality remain item 7 qualification work.
5. **Complete for M3 preview; M8 adapter work in progress:** format 5 provides versioned lifecycle execution, typed human/timer suspension, authenticated transport, fleet indexing and explicit hosting without changing formats 2–4. Separate saga and loop formats add stable child identities, reverse compensation and bounded iteration; a durable composite index and host continue their parents after restart. Local bounded content-addressed blob storage and driver-free HMAC-authenticated deduplicated webhook triggers now have restart/packed-consumer evidence. Shared object storage and broader hosted trigger adapters remain.
6. **In progress:** dependency-free headless run/human bindings preserve explicit network/cancellation control, bounded immutable state, stream-gap truth, conservative content-free activity timelines and text-only prompts in the isolated browser bundle. A strict content-free DAG projector covers durable formats 2–5, including required-child links, without workflow/storage dependencies; a separately bounded server adapter and browser client now provide authenticated read, cancellation and digest-bound exact-approval transport. Mutations are single-attempt, revision/command-bound and delegate atomic idempotency journaling to the application adapter. Inert human-response and workflow-control stores add explicit single-flight state, conflict classification and no automatic retry; a successful workflow controller cannot reuse its stale revision. The optional React adapter adds subscription-only hooks and semantic run/workflow/human/form components; its form is uncontrolled and submits nothing itself. The hook closure remains three packages; the separately typed component profile is five packages and ships no renderer. Broader signals/resume, refreshed-view coordination, workflow administration/listing, localization and live visual/accessibility qualification remain. Metadata-only OTLP/HTTP JSON logs, completed traces and fixed-catalog metrics have bounded unit and packed-consumer evidence; automatic native mapping and collector interoperability remain item 7 qualification work.
7. Define and execute the complete performance/evaluation suite, protected CI release workflow and first registry-provenance rehearsal.

Every item requires public contracts, denied/failure-path tests, packed-consumer evidence, documentation and a local Git checkpoint. This file must be updated as each slice closes; the active development goal remains open until every roadmap item has direct evidence.
