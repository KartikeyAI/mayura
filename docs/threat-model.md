# Mayura threat model

Status: **v1 release baseline** (F2 in the [v1 plan](v1-release-plan.md)). It records assets, trust boundaries, threats, the controls that address them with their evidence, and the risks that remain. Review it whenever a trust boundary, dependency or default changes. [SECURITY.md](../SECURITY.md) defines reporting and disclosure.

## Scope and assumptions

Mayura is a library and self-hosted runtime. The **application** that embeds it is trusted: its tools, schemas, guards, model adapters, hooks, authentication callback and adapters run in-process with full host authority. Permission declarations constrain what the runtime *dispatches*; they do not sandbox application code that chooses to import host APIs. Only Code Mode programs are treated as untrusted code.

Assets, in priority order: credentials and secrets; the integrity of external effects (no unauthorized, duplicated or forged effect); user and workflow content (inputs, outputs, memory, artifacts); audit and receipt evidence; budget and spend; availability.

Actors: authenticated operators and end users; unauthenticated network clients; browser origins; model providers and remote memory/MCP services (trusted for availability, untrusted for content); Code Mode programs (untrusted); webhook senders (authenticated by shared secret); co-tenants of the same database; supply-chain publishers.

## Trust boundaries

| # | Boundary | Primary threats | Controls | Evidence |
|---|---|---|---|---|
| 1 | Network → HTTP server | Spoofed identity; token leakage; cross-origin abuse; DNS rebinding and host confusion; request smuggling; resource exhaustion | Bearer tokens verified only by the application's `authenticate` callback, never trusted from claims; credentials never accepted in query strings, including on CORS preflight; exact allowed origins with no wildcard and no cookie authority; exact destination origin; the production host refuses any other `Host` with 421, requires HTTPS origins and adds HSTS; bounded headers, bodies, sockets, time and concurrent operations; upgrades refused | [http transport](specs/http-agent-transport.md), [production server](specs/production-server.md), `packages/server/test/server.test.ts`, `packages/server-node/test/*.test.ts` |
| 2 | Authenticated identity → authorization | Privilege escalation across scopes, agents or capabilities; confused deputy | Capabilities checked before body parsing and re-checked after every adapter call; scope and agent IDs derived from verified identity only; fleet-wide control requires the separate `workflows:fleet` capability; owner-scoped idempotency | server capability tests; [fleet control guide](how-to/fleet-control.md) |
| 3 | Server → application adapters | Adapter returning another run, stale state, or content-bearing data; hostile replies | Every adapter reply revalidated: exact keys, run identity, non-regressing revision, content-free views and sweep pages; malformed replies become `WORKFLOW_TRANSPORT_INVALID`; exceptions sanitized | workflow transport tests in `packages/server/test/server.test.ts` |
| 4 | Runtime → tools and external effects | Unauthorized, duplicated or replayed effects; budget overrun; lost evidence | Unified tool authority (permission, schema, guard, budget, timeout) before dispatch; durable dispatch intent and receipts; compare-and-set, claims and fences so concurrent drivers cannot double-dispatch; uncertain outcomes become `outcome_unknown` and are reconciled from evidence, never replayed; durable budget reservations; operator pause and fleet hold are quiescent and cannot bypass approvals | [unified tool authority](specs/unified-tool-authority.md), [durable execution](specs/durable-execution.md), [external effect reconciliation](specs/external-effect-reconciliation.md), [durable budgets](specs/durable-budget-ledger.md), process-kill recovery tests |
| 5 | Runtime → model providers | Prompt injection turning content into authority; data exfiltration to unintended destinations; runaway cost | Model output never grants permissions; tool calls go through boundary 4; provider adapters use fixed destinations and explicit credentials, pricing and budgets; guardrails and protected streaming withhold output until checks pass | [model provider contract](specs/model-provider-contract.md), [runtime-managed guardrails](specs/runtime-managed-guardrails.md), [processors](specs/processors.md) |
| 6 | Code Mode programs → host | Sandbox escape; host API access; resource exhaustion | QuickJS inner interpreter with no host capabilities except mediated calls; Docker outer sandbox with signed clean-scan image promotion, no network and escape-negative probes; bounded time, memory and output; durable phases prevent replay | [Code Mode](specs/code-mode.md), [QuickJS](specs/code-mode-quickjs.md), [Docker](specs/code-mode-docker.md), [promotion](specs/code-mode-docker-promotion.md) |
| 7 | Runtime → storage | Cross-scope reads; identifier aliasing; lost updates; tampered or corrupt state | Scope digests on every key; parameterized SQL; identifier integrity rejects unpaired surrogates; aggregate compare-and-set; strict state validators refuse corrupt or unknown layouts and unsupported schema versions; integrity-checked backups and verified restore | [storage aggregate](specs/storage-aggregate.md), [SQL identity integrity](specs/sql-identity-integrity.md), [storage operations](how-to/storage-operations.md) |
| 8 | Remote memory, MCP and webhooks | Stale or cross-scope memory resurrecting deleted data; MCP responses smuggling authority; forged or replayed webhooks | Remote memory hits rehydrated through native version and hash, tombstones win; MCP results accepted only as bounded structured JSON through the normal broker; webhooks HMAC-authenticated and deduplicated | [remote memory adapters](specs/remote-memory-adapters.md), `packages/adapter-mcp`, [webhook triggers](specs/webhook-triggers.md) |
| 9 | Framework → telemetry and network by default | Silent data egress or phone-home | No default network access or telemetry; exporters are explicit and metadata-only | [no default phone-home](specs/no-default-phone-home.md), [OTLP logs](specs/otlp-http-json-logs.md), [traces and metrics](specs/otlp-http-json-traces-metrics.md) |
| 10 | Browser UI | XSS via prompts or labels; unintended commands | Text-only rendering with no raw HTML; components emit intent only and start no request on mount; revision-bound single-flight command state | [React components](specs/react-components.md), [headless bindings](specs/headless-ui-bindings.md) |
| 11 | CLI and deployment | Credential exposure in arguments, history or logs; implicit code execution; container privilege | Operational tokens only through piped stdin; serve, worker and migrate import only an explicitly named regular module; images built offline from reviewed archives with a pinned base, running as a non-root user | [operational CLI](specs/authenticated-operational-cli.md), [deployment guide](how-to/production-deployment.md) |
| 12 | Supply chain and release | Malicious or vulnerable dependency; tampered artifacts; leaked secrets in archives | Exact dependency versions with qualification review; no install scripts in reviewed closures; archive inspection rejects tests, environment files and private keys; checksums bound to the source commit; provenance planned for publication | [technology qualification](technology-qualification.md), `scripts/release-artifact-check.mjs` |

## Residual risks and explicit non-goals

- **Trusted application code is not sandboxed.** A malicious or compromised tool, guard, adapter or hook can do anything the host process can. Run untrusted logic only through Code Mode.
- **Code Mode has not had an independent security audit** and is not qualified for hostile multi-tenant code (v1 plan F11).
- **Authentication quality is the application's responsibility.** Mayura verifies nothing about a token itself; weak `authenticate` callbacks weaken every boundary above.
- **Leadership leases assume bounded clock skew** (under a third of the lease). Exceeding it can cause overlapping hosts; correctness still rests on per-format compare-and-set and claims, so the cost is wasted work, not duplicated effects.
- **External effects are at-least-once with deduplication**, not exactly-once across arbitrary external APIs. Tools that are not idempotent need provider-side idempotency keys or reconciliation.
- **Ephemeral HTTP runs do not survive restarts.** With a submission journal a retry is refused rather than duplicated, but the earlier outcome is unknown to the new process.
- **Availability under targeted load** relies on the configured bounds and the deployment's own rate limiting; no DDoS protection is built in.
- **A database schema is isolation, not authorization.** Anyone with database credentials bypasses every application boundary.
- **Transport encryption behind a proxy** depends on the deployment keeping the plain-HTTP listener unreachable except through the TLS-terminating proxy.

## Review checklist for changes

A change that adds a network destination, a credential path, a new capability, an adapter reply shape, a default, a stored layout or a dependency must update the relevant row above, add a denial or failure-path test, and state any new residual risk.
